## 6 Â· Known limitations (read before go-live)

1. **Purchase/Sales tax model** is generic output/input tax (single rate per line). FBR-specific FED/advance tax variants are not modelled â€” configure rates to your actual business.
2. **FIFO is supported** (`costing_method = 'fifo'`), and weighted-average is the default; both are tested. Mixed costing per product is not supported.
3. **FIFO layer data is rebuilt only from `stock_cost_layers`**; if you switch costing methods mid-year, receive stock again or reconcile â€” layers are not back-filled.
4. **Bank reconciliation** is a summary view (GL book vs cleared cheques + pending items); it is not a full statement-matching engine with auto-match.
5. **Payroll** generates draft payslips; formulas = basic (monthly / weekly = rate Ã— present-weeks (6 working days/week) / daily Ã— present incl. Â½-day / hourly hours Ã— rate / fixed contract) + overtime (1.5Ã— derived rate or custom `overtime_rate`) + outstanding advances minus loan installments deducted; no tax (FBR payroll tax) engine, gratuity/EOBI/PESSI are outside scope. Weekly payroll period = any 7-day range you pick.
6. **No partial-delivery** tracking on sales orders (order â†’ invoice is manual); orders are planning documents only.
7. **PDF export** = browser print (â€œSave as PDFâ€). Native server-side PDF is not bundled (no Composer/Node on shared hosting by design).
8. **Two-factor authentication** is not yet implemented (the schema has `force_password_change`; 2FA columns can be added later). Password resets are admin-driven (Users â†’ Edit) rather than self-service email (Hostinger shared mail can be used later).
9. **Multi-currency / multi-branch GL consolidation** are not implemented â€” single currency (PKR), branches track documents but reports are company-wide.
10. **Costing of sales returns** uses the cost recorded on the original invoice line â€” correct and traceable, but manual journal overrides won't flow into inventory value.
11. **The installer writes `config/config.php`**; local `config/config.php` (SQLite dev) must NOT be uploaded to production. `.gitignore` excludes it.
12. Demo data (`seed_demo.php`) is for evaluation only â€” **never** load it in production; it posts labelled demo journals and demo opening stock (Rs 1,065,000 Cr Owner Capital).
13. Stock valuation report groups by warehouse; FIFO display `avg_cost` is a derived display value.
14. Concurrency: voucher numbering uses atomic upsert (safe), but the app targets single-branch usage patterns typical for Hostinger shared hosting â€” very high-concurrency writes are serialized by MySQL/InnoDB anyway.
